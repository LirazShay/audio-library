# אפיון UX/UI וחוויית ההאזנה — ספריית שמע דינמית
**גרסה:** 1.0  
**סטטוס:** מסמך אפיון UX/UI  
**מבוסס על:** מסמך דרישות מוצר 1.0 + אפיון פונקציונלי 1.0 + מודל התוכן וה־Generator 1.0  
**מטרת המסמך:** להגדיר איך המוצר ייראה, ירגיש ויתנהג מבחינת המשתמש — עם דגש על חוויית האזנה מרשימה, פשטות, נוחות, RTL, מובייל ודסקטופ.

---

# 1. עקרון החוויה

האתר צריך להרגיש כמו **ספריית שמע איכותית ומודרנית**, לא כמו תיקיית קבצים ולא כמו אתר טכני.

המשתמש צריך להרגיש שהמוצר נבנה במיוחד עבור האזנה:

- קל למצוא תוכן.
- קל להבין איפה נמצאים.
- קל להתחיל להאזין.
- הנגן מרשים וברור.
- הטקסט מוצג כחלק מהחוויה.
- המעבר בין קטעים פשוט.
- אין עומס כפתורים.
- אין מונחים טכניים מיותרים.
- כל פעולה ברורה גם למשתמש לא טכני.

העיקרון המנחה:

> **מרשים מבחינה חזותית, פשוט מבחינה שימושית.**

# 2. עקרונות UX מחייבים

## 2.1 פשטות לפני צפיפות

כל מסך צריך לענות על שאלה אחת מרכזית.

לדוגמה:

- בית → מה אני רוצה לשמוע?
- נושא → איזה קטע לבחור?
- קטע → להאזין ולקרוא.
- חיפוש → למצוא תוכן.
- מועדפים → לחזור לדברים ששמרתי.

## 2.2 Audio First

הנגן אינו רכיב צדדי.

הוא לב המוצר.

לכן:

- פקדי הנגן בולטים.
- מצב הניגון ברור.
- הטקסט משולב לידו.
- Progress תמיד נגיש.
- המשתמש לא צריך לחפש את כפתור Play.

## 2.3 Mobile First

העיצוב יתחיל מהמובייל.

אחר כך יתרחב לדסקטופ.

הסיבה:

- האזנה נעשית פעמים רבות מהטלפון.
- פקדים גדולים חשובים.
- הטקסט צריך להישאר קריא.
- Mini Player צריך לעבוד היטב בתחתית.

## 2.4 RTL First

הכיוון הראשי של הממשק הוא RTL.

כל:
- טקסט.
- ניווט.
- Breadcrumb.
- רשימות.
- כפתורים עם מלל.

צריכים להרגיש טבעיים בעברית.

# 3. מבנה הניווט הראשי

הניווט הראשי צריך להיות קצר.

פריטים מרכזיים:

```text
בית
נושאים
חיפוש
מועדפים
היסטוריה
```

לא צריך יותר מזה בגרסה א'.

## 3.1 מובייל

מומלץ להשתמש באחת משתי גישות:

### אפשרות מועדפת
Bottom Navigation קטן:

```text
בית | נושאים | חיפוש | מועדפים | היסטוריה
```

יתרונות:
- נגיש באגודל.
- מוכר.
- לא תופס Header.

### חלופה
Header עם כפתור תפריט.

אם Bottom Nav ירגיש עמוס מדי, עוברים לחלופה.

## 3.2 דסקטופ

אפשר להשתמש ב־Sidebar צר או Header עליון.

לא חובה להציג Sidebar קבוע אם הוא מקטין את אזור הטקסט והנגן.

---

# 4. Header

Header צריך להיות נקי.

יכלול לפי המסך:

- לוגו/שם האתר.
- Back במובייל.
- חיפוש.
- מצב האזנה קטן.
- אולי כפתור Menu.

לא להעמיס:
- עשרה אייקונים.
- הגדרות לא שימושיות.
- נתונים טכניים.

---

# 5. דף הבית

## 5.1 מטרת המסך

להכניס את המשתמש לתוכן מהר.

## 5.2 מבנה מומלץ

```text
שם / לוגו

חיפוש מרכזי

המשך להאזין

נושאים

מועדפים / היסטוריה
```

## 5.3 חיפוש

שדה חיפוש גדול וברור.

Placeholder לדוגמה:

```text
חפש לפי שם קטע או נושא
```

לא להציג Search Advanced.

## 5.4 המשך להאזין

כרטיס בולט אך לא ענק.

מכיל:

- שם קטע.
- שם נושא.
- Progress.
- זמן נוכחי / משך אם ידוע.
- כפתור "המשך".

הכרטיס כולו יכול להיות לחיץ.

## 5.5 נושאים

נושאים יוצגו ככרטיסים גדולים.

במובייל:
- 1–2 בעמודה בהתאם לרוחב.

בדסקטופ:
- Grid.

כל כרטיס:
- שם.
- מספר קטעים/תתי־נושאים אם שימושי.
- אולי אייקון/גרפיקה עדינה.

לא צריך תמונה לכל נושא בגרסה א'.

# 6. מסך "כל הנושאים"

מטרתו להציג את הרמה העליונה.

כל Topic מוצג ככרטיס.

אם קיימים Tracks ישירות בשורש:
- מציגים גם אותם באזור נפרד מתחת לנושאים.

לא מציגים למשתמש:
```text
content/
folder
directory
```

# 7. מסך נושא

## 7.1 מבנה

```text
Breadcrumb / Back
שם הנושא
מספר פריטים

תתי־נושאים

קטעי שמע
```

## 7.2 תתי־נושאים

כרטיסים פשוטים.

כל כרטיס:
- שם.
- חץ/סימון שמדובר בניווט.
- מספר פריטים אופציונלי.

## 7.3 רשימת קטעים

מומלץ List ולא Grid.

למה:
- שמות יכולים להיות ארוכים.
- קל יותר לראות סדר.
- מתאים להאזנה רציפה.

כל שורה:

```text
[Play] שם הקטע
       משך / Progress
       Favorite
```

## 7.4 הקטע שמתנגן כרגע

השורה שלו צריכה להיות מובחנת.

למשל:
- רקע עדין.
- אייקון Playing.
- Progress קטן.

לא להשתמש באנימציה אגרסיבית.

---

# 8. מצב האזנה ברמת הנושא

במקום להחביא Shuffle/Autoplay כאייקונים לא ברורים, מציגים **מצב האזנה** בשפה פשוטה.

כפתור לדוגמה:

```text
מצב האזנה: המשך אוטומטי
```

לחיצה פותחת Bottom Sheet / Popover.

---

# 9. בחירת מצב האזנה

החלון יציג:

```text
איך תרצה להאזין?
```

אפשרויות:

### שיר בודד
בסיום הקטע הנגן נעצר.

### המשך אוטומטי
בסיום כל קטע עוברים לקטע הבא ברשימה.

### בחירה חופשית
אתה בוחר בכל פעם את הקטע הבא.

### ערבוב אוטומטי
בסיום כל קטע נבחר קטע אחר מתוך הרשימה.

הבחירה הפעילה מסומנת בבירור.

אין צורך להציג:
```text
Queue
Shuffle
Autoplay
Mode ID
```

---

# 10. הערה לגבי "שיר בודד" ו"בחירה חופשית"

מבחינת התנהגות הם עשויים להרגיש דומים.

לכן:

- נציג אותם בשלב האבטיפוס.
- בבדיקת UX נבדוק האם המשתמשים מבינים את ההבדל.
- אם ההבדל אינו משמעותי, נאחד אותם.

לא משאירים כפילות רק בגלל שהוגדרה מוקדם.

# 11. מסך Track — המסך החשוב ביותר

זהו המסך שבו צריך להשקיע הכי הרבה.

המטרה:

> לתת חוויה כל כך טובה, שגם בלי וידאו המשתמש ירגיש שהוא במוצר עשיר ומיוחד.

# 14. כותרת הקטע

תוצג בצורה בולטת.

מתחתיה:
- שם הנושא.
- אולי Breadcrumb קטן.

לא להציג:
- file path.
- extension.

# 15. Visualization

זהו האלמנט שנותן תחושת "יותר מסתם Audio".

המלצה לגרסה א':

### Progress Visualization אלגנטי

למשל:
- waveform פשוט.
- bars עדינים.
- ring סביב Play.

העדיפות:

> **אלמנט שנותן חיות אך אינו גונב תשומת לב מהטקסט ומהנגן.**

---

# 16. Progress Ring

אפשרות מומלצת:

כפתור Play/Pause גדול בתוך טבעת Progress.

יתרונות:
- נראה ייחודי.
- שימושי.
- ברור.
- לא דורש וידאו.

דוגמה רעיונית:

```text
      ◜──────────◝
     │     ▶      │
      ◟──────────◞
```

הטבעת מתמלאת בהתאם להתקדמות.

---

# 17. Waveform

אם נבחר Waveform:

- הוא לא צריך להיות מדויק ברמת Studio.
- הוא יכול להיות Visual representation.
- אם קל להפיק Waveform ב־Generator בעתיד, נשקול.
- בגרסה א' לא לחייב חישוב מורכב.

אפשר להתחיל ב־Progress Bar מעוצב מאוד.

---

# 18. כפתור Play/Pause

זהו הכפתור החשוב ביותר.

דרישות:

- גדול.
- במרכז.
- Tap target גדול.
- מצב Play/Pause מובן מיד.
- לא תלוי בטקסט.

במובייל:
- לפחות בגודל נוח לאגודל.

---

# 19. פקדי ±10 שניות

משני צדי Play:

```text
10-     ▶/Pause     +10
```

עדיף טקסט/אייקון שמבהיר את מספר השניות.

לא להשתמש באייקון לא ברור.

---

# 20. Previous / Next

יהיו נגישים אך פחות בולטים מ־Play.

אפשר:

```text
⏮    -10    Play    +10    ⏭
```

אבל חשוב לא ליצור שורה צפופה מדי.

במובייל ניתן לפצל לשתי שורות אם צריך.

---

# 21. פס התקדמות

צריך להיות:

- רחב.
- נוח לגרירה.
- בעל thumb ברור.
- עם זמן נוכחי.
- עם משך כולל.

דוגמה:

```text
12:34 ━━━━━━━━━●━━━━━━━━ 42:15
```

# 22. Playback Speed

כפתור קטן:

```text
1×
```

לחיצה פותחת:

```text
0.75×
1×
1.25×
1.5×
1.75×
2×
```

הערך הפעיל מסומן.

לא צריך Slider.

---

# 23. Repeat

Repeat שייך למסך Track.

הטקסט המועדף:

```text
חזור על הקטע
```

או אייקון Repeat עם Tooltip/Label ברור.

כאשר פעיל:
- מצב חזותי ברור.
- לא משנים את מצב ההאזנה הכללי.

---

# 24. Volume

בדסקטופ:
- אייקון + Slider.

במובייל:
- ניתן להסתפק באייקון Mute או אפילו להשמיט Volume UI ולהסתמך על המכשיר.

אין צורך להציג פקד שאינו באמת שימושי.

---

# 25. טקסט

הטקסט הוא רכיב מרכזי.

דרישות:

- פונט קריא.
- שורות עם מרווח נדיב.
- רוחב קריאה נוח.
- RTL.
- שמירת מעברי שורה.
- ללא HTML interpretation.
- ללא עיצוב יתר.

---

# 26. מיקום הטקסט

במובייל:
- מתחת לנגן.

בדסקטופ:
- ליד הנגן או מתחתיו, בהתאם לרוחב.

המטרה:
- המשתמש רואה את הנגן ואת הטקסט בלי לקפוץ בין מסכים.

---

# 27. Sticky Player Controls בזמן קריאת טקסט

כאשר הטקסט ארוך:

- פקדי Play/Pause בסיסיים צריכים להישאר נגישים.

אפשר:
- Mini sticky control קטן בתוך מסך Track.
- או Header קטן בזמן Scroll.

לא לשכפל את כל הנגן.

---

# 28. אין טקסט
